# Render deployment and architecture review

## Architecture

Flask serves the three static frontend files and JSON API from one origin. No Node build is required. Sessions, passwords, fragment progress, history, hints and confirmation attempts live in a process-local dictionary. SQLite stores event logs, not resumable game state. Keyword matching and direct substring guesses decide unlocks; Groq only generates dialogue. Responses are JSON, not streamed. `claude_client.py` is not imported by the live app; `score_teams.py` is a separate optional Gemini scoring tool.

## Deploy

1. Push this repository, including `render.yaml` and `backend/gunicorn.conf.py`, to GitHub. Do not commit `.env`, databases or participant CSV exports.
2. Open https://dashboard.render.com/ and choose New > Blueprint; connect `Akshitad23/Kalakriti_PromptEngineering` and the branch containing these changes.
3. Use the free service defined by the Blueprint. Supply GROQ_API_KEY for live dialogue, or an empty value for fallback mode. ADMIN_PASSWORD is generated by Render: retrieve it from the service environment settings.
4. Deploy and open the service's actual HTTPS URL. Check `/api/health`, then start a unique team, chat, request a hint, unlock fragments, and confirm the assembled password.
5. After five minutes of active browser countdown, select a challenge card. Verify all six card types over separate sessions. Try three incorrect confirmations and a timeout in separate sessions.
6. Download `/api/admin/export` using the `X-Admin-Key` header. The legacy `?key=` form also works; use the generated password, not the old published default. Export before restarts if logs matter.

Manual equivalent: leave Root Directory empty; build `pip install -r backend/requirements.txt`; start `cd backend && gunicorn --config gunicorn.conf.py app:app`; health check `/api/health`; Python 3.12.10. The repo root keeps the sibling frontend available.

## Demo limitations and review findings

- Keep one serial worker and one instance. More workers lose access to each other's sessions; threads would race on mutable state. This setup queues players' Groq requests and is suitable only for a small demo. Shared storage, locks and rate limits are needed for larger public use.
- Render free services sleep after inactivity. All live sessions and local SQLite logs are lost on restart, redeploy or sleep.
- Team names identify sessions without authentication. Anyone who knows a team name can act on it. Add session-token authorization before using this as a competitive public event.
- The countdown, card selection, pauses, time bonuses, prompt caps and length restrictions are browser-controlled. They are not tamper-resistant. The backend clock starts at team entry, while the visible countdown starts after briefing; elapsed scoring therefore differs. The new challenge endpoint only checks server elapsed time and prevents repeated backend effects. It does not validate the browser's random card selection.
- Timeout now closes a session against later chat, hint and confirmation calls. It still relies on the browser to report timeout. A full authoritative timer requires mission-start and challenge-pause/resume APIs.
- Direct guesses use substring matching, including symbols, making incidental matches possible. This is a designed keyword game rather than a measurement of model jailbreak success.
- CSV export scoring is fragments * 20 + 40 for a full win - 15 for a hint. The separate Gemini script computes a different score out of 10. The frontend displays prompts/time/hints, not a unified score.
- Missing-key fallback now includes fragment hints. Groq SDK retries are disabled and network timeout is explicit. Admin endpoints are disabled if no password is configured; keyword debugging requires admin authentication.

## Verification status

Local automated checks use an isolated temporary SQLite file and mocked or disabled Groq; they do not modify event logs or spend API credits. Gunicorn requires Linux and must be verified on Render. Live cloud URL, real Groq credentials, audio/visual behavior and the five-minute UI interaction remain live-browser checks after deployment.
